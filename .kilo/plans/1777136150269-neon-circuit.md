# 前端性能分析 & 优化计划

## 现状诊断

项目是基于 Hugo 的静态网站（AwesomeVideoPrompts.com），展示 2,470 条 AI 视频提示词。当前 `public/index.html` 单文件体积为 **5.1 MB**。

## 核心问题 & 优化方案

### 1. 🔴 致命：首页 JSON 数据内嵌过大（5.1 MB HTML）

**问题位置**：`layouts/index.html:51-65`

```html
<script type="application/json" id="prompts-data">
  [所有 2470 条提示词的完整 JSON 数据]
</script>
```

每一条提示词包含 title、description、image、video、model、tags、author、date、sourceUrl、permalink、filename 全部字段。2,470 条数据序列化后占 HTML 体积的 ~90%。

**影响**：
- TTFB（首字节时间）极大
- FCP/LCP 严重延迟
- 浏览器需解析 5MB 数据并构建 2,470 个 JS 对象
- 用户访问首页即使只看 10 张卡片也要下载全部数据

**优化方案**：
- **方案 A（推荐）**：外部 JSON 文件。将 `prompts-data` 改为独立 JSON 文件（`/api/prompts-index.json`），首页通过 `fetch()` 按需加载。可配合 gzip/brotli 压缩。
- **方案 B**：分页 JSON API。拆分为多个小文件（如 `/api/prompts-page-1.json`），无限滚动时按需 fetch。
- **方案 C**：精简字段。移除前端不需要的字段（如 `filename`、`permalink`部分），减少 JSON 体积。

**预期收益**：首页 HTML 从 5.1 MB → **< 50 KB**，TTFB 降低 99%。

---

### 2. 🔴 致命：`prompt-card.html` 内联 `<script>` 重复定义

**问题位置**：`layouts/partials/prompt-card.html:88-119`

每次渲染一张卡片，都输出一个 `copyPromptText()` 函数定义。noscript 回退渲染 50 张卡片时，产生 50 个完全相同的函数定义。

**优化方案**：
- 将 `copyPromptText()` 移到 `baseof.html` 全局脚本中，使用事件委托（已有类似逻辑在 baseof.html:1468-1620）
- 或删除 partial 中的 `<script>` 块，依赖全局 `event delegation` 处理复制

**预期收益**：减少 HTML 体积，消除重复函数定义导致的 JS 解析开销。

---

### 3. 🟡 严重：CSS/JS 全部内联，无浏览器缓存能力

**问题位置**：
- CSS：`baseof.html:55-1181`（~1100 行），以及各页面 `define "head"` 块
- JS：`index.html:68-910`（~840 行），`models/term.html:367-758`（~400 行），`models/taxonomy.html:243-634`（~400 行）

**问题**：
- 每次页面导航都需要重新下载完全相同的 CSS/JS
- 无法利用浏览器磁盘缓存
- 无法使用 CDN 边缘缓存

**优化方案**：
- 提取全局 CSS 为独立文件（`assets/css/main.css`），通过 Hugo Pipes 处理（指纹化 + 压缩 + Source Map）
- 提取全局 JS 为独立文件（`assets/js/main.js`），同样通过 Hugo Pipes
- 使用 `resources.Concat` 合并 + `resources.Minify` 压缩
- 模板中通过 `{{ $style.Permalink }}` 引用，自动带版本指纹

**预期收益**：浏览器可缓存 CSS/JS，后续页面加载减少 ~50KB 传输量。

---

### 4. 🟡 严重：JS 逻辑在多个页面重复

| 文件 | JS 行数 | 重复内容 |
|------|---------|----------|
| `index.html` | ~840 | 完整 masonry + filter + lazy load |
| `models/term.html` | ~400 | 同上（model 专属版） |
| `models/taxonomy.html` | ~400 | 同上（model 专属版） |
| `_default/taxonomy.html` | ~68 | 简化 masonry |
| `_default/gfeed.html` | ~260 | 简化 masonry |

**优化方案**：
- 提取共享逻辑到公共 JS 模块（masonry 布局、筛选、懒加载）
- 模块化：`masonry.js`、`filter.js`、`lazy-load.js`
- 各页面只包含差异部分（如特定初始化参数）

---

### 5. 🟡 中等：图片缺少显式尺寸导致 CLS

**当前状态**：
- 图片无显式 `width`/`height`，引起 CLS（布局偏移）
- 首屏图片未标记 `fetchpriority="high"`

**优化方案**：
- 添加 `width`/`height` 属性防止 CLS
- 首屏卡片图片添加 `fetchpriority="high"`
- 保持现有 JPEG 格式不变，不做格式转换

---

### 6. 🟡 中等：Google Fonts 加载策略可优化

**当前**：`Outfit` 字体通过 Google Fonts CDN 加载，`display=swap`

**优化方案**：
- 自托管字体文件（`/static/fonts/outfit-*.woff2`），配合 `@font-face` + `font-display: optional`
- 或添加 `preload` 提示加速首屏字体加载
- 预加载关键字体子集（Latin only）

---

### 7. 🟡 中等：视频 hover 预览的触发策略

**当前**：
- 每张卡片都包含 `<video>` DOM 节点（`prompt-card.html:23`）
- 视频 `data-src` 在 hover 时才赋值 `src` 并加载 — 这个设计本身较好
- 但 DOM 体积仍然不小（~~120 字符/卡片 × 2,470 = ~~296KB 额外 DOM）

**优化方案**：
- JS 渲染的卡片已经按需创建 video 元素，问题不大
- Hugo 服务端渲染的卡片（noscript 回退 / 标签页）可改为客户端按需创建 video 元素

---

### 8. 🟢 较低：调试日志残留

多处 `console.log()` 调用在生产代码中：
- `index.html:167`, `index.html:318`, `index.html:338`, `index.html:376` 等
- `models/term.html`, `models/taxonomy.html` 中同样存在

**优化方案**：移除或条件化（仅在开发环境输出）。

---

### 9. 🟢 较低：缺少资源预加载提示

- 缺少 `<link rel="dns-prefetch">` 或 `<link rel="preconnect">` 针对媒体资源域名
- 缺少 `preload` 关键资源（如上导航 SVG icon）

---

## 实施优先级

> **排除项**：图片格式转换（WebP/AVIF）不在本次优化范围。

| 优先级 | 项目 | 预期收益 | 工作量 |
|--------|------|----------|--------|
| P0 🔴 | JSON 数据外置（方案 A） | 首页 5.1MB → <50KB | 中 |
| P0 🔴 | 消除 partial 重复 script | 减少 HTML 体积 + JS 解析 | 低 |
| P1 🟡 | CSS/JS 模块化 + 外部文件化 | 浏览器缓存，后续页加载快 | 中 |
| P1 🟡 | 图片 width/height + fetchpriority | CLS 消除，LCP 提升 | 低 |
| P2 🟡 | JS 去重合并 | 减少维护成本 | 中 |
| P2 🟡 | Google Fonts 优化 | 字体加载快 | 低 |
| P3 🟢 | 移除 console.log | 减小 JS 体积 | 低 |
| P3 🟢 | 资源预加载提示 | 微优化 | 低 |
